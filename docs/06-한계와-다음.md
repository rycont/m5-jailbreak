# 06 · 한계와 다음

## 지금 남은 것

### 1. 입력 포워딩

가장 큰 구멍입니다. Sway는 화면을 그리고 있지만 키보드/마우스는 Tizen 쪽에 있습니다. `WLR_LIBINPUT_NO_DEVICES=1`로 libinput을 아예 끈 상태입니다.

가능한 경로:

- Tizen 입력 데몬에서 이벤트를 받아 Wayland 클라이언트로 주입
- `/dev/uinput`이 열린다면 가상 장치로 재생
- E의 Tizen 확장(`tizen_policy`)을 Sway 쪽에 브리지

아직 검증되지 않았습니다. 다음 사례의 주제로 적합합니다.

### 2. 3D 가속

Mali용 Mesa는 있지만 GBM이 없어 wlroots의 GL 렌더러가 버퍼를 잡을 수 없습니다. 현재 pixman(CPU)이라 1080p에서 터미널·계산기 수준은 충분하지만 브라우저/이미지 편집은 무겁습니다.

가능한 경로:

- TBM dmabuf를 EGL로 감싸는 커스텀 wlroots 렌더러
- TPL-EGL과 `linux-dmabuf`를 직접 연결
- 이는 "GBM shim"보다 큰 작업입니다 ([01](01-스택-지도.md))

### 3. 부팅 자동화

재부팅하면 벤더가 master를 다시 잡습니다. 현재는 수동으로 `kmsown2`/패치를 다시 해야 합니다. 자동화하려면:

- 부팅 시 master 보유 여부 확인
- 필요할 때만 패치 (주소 재탐색 포함)
- Sway 기동, 실패 시 벤더 UI로 폴백

부트로더를 건드리지 않는 범위에서 서비스 유닛이나 감시 스크립트로 풀어야 합니다.

### 4. Tizen UI와의 공존

E는 죽일 수 없으므로 계속 살아 있습니다. 화면만 Sway가 가져가는 구조라, 입력·알림·밝기 같은 것은 여전히 Tizen 쪽입니다. 완전한 대체가 아니라 **출력만 탈취한 상태**입니다.

## 참고: 이 저장소가 하지 않은 것

- 부트로더 언락/수정
- 파티션 변경
- Tizen 서명 우회 도구 배포
- 다른 사람의 기기에서의 재현 보장

기기·펌웨어·커널이 다르면 주소와 ioctl 동작이 달라집니다. 이 문서는 **한 대의 M5에서 실제로 확인한 기록**이지, 모든 M5에 대한 보편 공식이 아닙니다.
