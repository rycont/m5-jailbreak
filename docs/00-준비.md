# 00 · 준비

## 필요한 것

- 삼성 M5 스마트 모니터 (Tizen, Linux 4.1 armhf)
- USB 케이블과 PC의 `sdb`
- 기기 전체를 뜰 수 있는 저장 공간 (실측 2.7GB, 여유 있게 8GB 이상)
- Debian trixie armhf rootfs (hard-float) — `/opt/usr/a/trixie`에 풀어 쓸 공간
- armhf 크로스 컴파일러 또는 기기 내부 gcc

## 접속 확인

```sh
sdb devices
sdb connect <모니터 IP>:26101
sdb shell
```

`sdb shell`은 기본적으로 **`sdk`(uid 901) 셸**입니다. `sdb root on`으로는 root가 되지 않습니다. root와 SSH 셸을 얻는 실제 경로는 [01 · 루트와 셸](01-루트와-셸.md)에 따로 정리했습니다.

루트 셸에서도 **CAP_KILL은 없습니다.** 다른 PID 네임스페이스의 프로세스(벤더 컴포지터 등)는 `kill`로 정리할 수 없습니다. 이 제약이 이후 모든 설계를 결정합니다: "죽여서 비우는" 대신 "master만 빼앗는" 쪽으로 갑니다.

## 백업

가장 먼저 eMMC를 통째로 뜹니다. 이 저장소의 실측에서는 **p1~p24, 합계 2.7GB**였습니다.

```sh
# 루트 셸에서 실제 파티션 노드를 먼저 확인
cat /proc/partitions

# 예: /dev/mmcblk0pN 을 외부 저장소로
for n in $(seq 1 24); do
  dd if=/dev/mmcblk0p$n of=/mnt/usb/m5/p$n.img bs=4M
done
sha256sum /mnt/usb/m5/*.img > /mnt/usb/m5/SHA256SUMS
```

포인트:

- 이미지와 체크섬을 **기기 밖**에 둡니다.
- 복원 명령을 미리 적어두고, 복원 가능한지까지 확인합니다.
- 부트로더·fstab·파티션 테이블은 건드리지 않습니다. 이 저장소의 모든 작업은 `/opt/usr/a`와 런타임 상태 안에서 끝납니다.

## 작업 공간

```
/opt/usr/a/                 # 앱존 작업 루트
/opt/usr/a/trixie/          # Debian trixie armhf rootfs
/opt/usr/a/libdrmcap.so     # Sway용 shim
/opt/usr/a/drmsway.sh       # 실행 스크립트
/tmp/m5drm.config           # Sway 설정 (재부팅 시 휘발)
```

## 로더 함정

Tizen 사용자 공간은 **softfp**, trixie는 **hard-float**입니다. 그리고 `CAP_SYS_CHROOT`이 없어서 chroot로 들어갈 수 없습니다. 그래서 trixie 바이너리는:

1. ELF 인터프리터를 `/opt/usr/a/trixie/lib/ld-linux-armhf.so.3`로 바꾸고
2. `LD_LIBRARY_PATH`로 trixie 라이브러리를 먼저 보게 합니다.

```sh
patchelf --set-interpreter /opt/usr/a/trixie/lib/ld-linux-armhf.so.3 \
  /opt/usr/a/trixie/usr/bin/sway
```

이 조합 없이 실행하면 `GLIBC_2.xx not found` 또는 `No such file or directory`(인터프리터 불일치)로 죽습니다.
