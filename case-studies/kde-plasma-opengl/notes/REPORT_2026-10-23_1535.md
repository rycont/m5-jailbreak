## 1. 패널 fps — 16.0/s (60 미달)

측정 명령(요지):
```sh
grep -c '\[OSD\] commit' /tmp/relay_fix7.log      # 시작/끝
dd if=/dev/fb1 bs=7680 skip=600 count=1 | md5sum  # y=600 한 줄 해시
awk '{print $14+$15}' /proc/3798/stat              # KWin CPU ticks
awk '{print $14+$15}' /proc/1122/stat              # relay CPU ticks
```
실측(15:04, 12.304초):
```
samples=90 changes=1 elapsed_ns=12304288914 commits=197 kwin_ticks=309 relay_ticks=35
commit_fps=16.01   row_change_rate=0.08/s
KWin CPU=25.1% (1코어 기준)   relay CPU=2.84%
```
- 1프레임당 62.5ms. KWin CPU 15.6ms/프레임, relay 1.8ms/프레임으로 **어느 쪽도 포화 아님**.
- relay는 벽시계의 97%를 present/commit 경로에서 블록된 채 대기 → 병목은 **KWin→relay→OSD present 핸드셰이크**.
- animclient는 900프레임을 62.892초에 전송(14.31fps). wl_buffer release 백프레셔에 막혀 **클라이언트 송신 fps = 패널 소비 fps**가 됐다.
- fb1 y=600 해시는 12.3초에 1회만 변했다. 당시 화면이 정지된 4-pane 뷰였기 때문이며, KWin은 같은 내용을 16회/초 다시 commit했다. 원문: `fps_measure_2026-10-23_1504.txt`.

1차 측정(14:58, 12초)도 초당 commit 15,14,14,14,14,15,14,15,14,15,14,14 = **15.4/s**로 같다.

## 2. KWin Mali 직접 렌더 — 확인

- KWin 로그: `eglMakeCurrent ... -> 1` 성공 **4,735회**, EGL context `0xb6955280`.

- relay 수신: `[DMABUF] create_immed 1920x1080 fmt=0x34325258`, 월페이퍼 프레임 `[OSD] readback=693084ff`(검정 아님).
