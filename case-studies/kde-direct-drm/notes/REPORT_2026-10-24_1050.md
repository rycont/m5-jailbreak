# 2026-10-24 10:50 KST — reboot reproduction: SUCCESS

The M5 was power-cycled (smart plug OFF, then ON with the mute bit kept).
Root SSH was restored with `restore_after_powercycle.sh`. The stored
`/opt/usr/a/m5kde/direct/start_direct_kde.sh` was then run **without any
manual KWin/Plasma setup**.

## Result

- `kwin_wayland --drm --socket wayland-4` = PID `2945`, alive.
- `plasmashell` = PID `3472`, alive.
- `dbus-daemon` on `unix:path=/tmp/dbus-kde` = PID `2935`.
- `org.kde.plasmashell` and `org.kde.KWin` registered.
- No relay process.
- Screen: **green desktop + bottom Plasma panel with the clock 10:50**.
  Evidence: `evidence/m5-kwin-direct-reboot-2026-10-24.png`.
- `uptime` at capture: 5 minutes (fresh boot).

## Reproduction issue found

The stored script called `python3` to apply the library patch, but this Tizen
root has no `python3`. The patched `/opt/usr/a/lib/libkwin.so.6` is persistent,
so the script now runs the patcher only if `python3` exists and otherwise uses
the existing patched library. After that one-line change, the direct KDE path
came up exactly as before.
